## 1. What this is

BSIT Survival Kit is a Next.js + Supabase + PayMongo study app for Philippine IT
students, deployed on Vercel. The owner is a solo founder.

We are building **four standing "department agents"** that read production, rank what
they find by whether it deserves interruption, and hand back *options* rather than
verdicts — so that "what is happening inside the product" becomes something read
rather than investigated.

## 4. Decisions already made — do not re-litigate

A fresh session will be tempted to redo these. They were argued through; each has a
reason.

1. **Collector / interpreter split.** Collectors are deterministic TypeScript, cost
   zero tokens, and are unit-tested. Interpreters are subagents that do judgment only.
   **Every number in a report must come from tested code, never agent arithmetic.**
   This is the core promise — the collector even renders the metrics table so PULSE
   only pastes it.
2. **Reports are gitignored, permanently.** The repo is public. Reports carry traffic,
   revenue, conversion, and security findings. A security report in a public repo is a
   published attack surface. Same rule that keeps `docs/POST-MORTEM.md` private.
3. **Session-bound invocation, not cron.** Rejected launchd/cron because: the Mac must
   be awake; a scheduled job runs in a near-empty environment where `node` is not even
   on `PATH` (it lives under nvm); and a silently-stopped schedule looks like good news.
   Upgrade path if this changes: a private reports repo + cloud runner.
4. **Credentials are split.** `.env.reports.local` holds production Supabase creds and
   is read only by `scripts/reports/*`. `.env.local` has **no** Supabase values, so
   `npm run dev` cannot write to the live database and pollute the very dataset Growth
   reads.
5. **Severity taxonomy**, with `ACCEPTED` as a first-class label requiring a reason
   *and* a reopen trigger. An ACCEPTED finding is never re-argued until its trigger
   fires. This is what stops a weekly report from nagging.
6. **Every finding carries options A/B/C, where A is always "do nothing," argued
   honestly.** For a solo founder, not acting is usually correct.
7. **Dashboard report format**, and detail is written only for the top finding plus
   every P0/P1. A report nobody finishes reading has failed.
8. **All departments run in ONE invocation.** A cold invocation costs ~22 US cents in
   cache-creation overhead before any analysis. Four separate runs pay that four times
   and lose the council.
9. **Council needs 2+ departments.** With one built there is no council; faking one is
   forbidden.
10. **Manila dates everywhere** — collector filenames and agent reads both use
    `Asia/Manila`. UTC would silently misfile between midnight and 8am.
11. **No local build check in the collector.** `npm run build` fails here by design
    (no Supabase creds in `.env.local`). Vercel's build is authoritative; PULSE reads
    it via `list_deployments`.
12. **Build order: Ops → Growth → Finance → Security.** Ops went first because it was
    *cheapest* (the `vercel-status` procedure already existed), so the shared machinery
    got debugged against the easy case rather than the hardest one.

## 5. Known bugs — fix these first

All three are small. The first matters most.

### 5.1 PULSE cannot see the migrated hosting history (**highest priority**)

`.claude/agents/pulse.md` Step 1 globs `docs/reports/ops/*.md`. The migrated hosting
reports live in `docs/reports/ops/hosting/*.md`. So the history that was moved *to
preserve continuity* is invisible to the agent meant to read it.

**Observed consequence:** the first PULSE run declared itself a baseline with "no prior
report to diff against" while a hosting report carrying five open findings existed.
Five open findings were silently dropped. A later run caught it and reinstated them.

Silently losing open findings makes the whole log untrustworthy. Fix the glob so Step 1
considers both directories, and make the report state which prior report it diffed
against.

### 5.2 Same-date re-runs overwrite published data

`scripts/reports/ops.ts` writes `docs/reports/ops/.data/<Manila-date>.json`. Running it
twice on the same Manila day overwrites the first file — so a report already published
from the earlier run now cites numbers its source no longer contains.

Fix: refuse to overwrite, or version within the day, or make the report record the
collector run it used.

### 5.3 `$0` in a skill file is substituted with the invocation argument

`.claude/skills/report/SKILL.md` contains `$0.22`, which renders as `ops.22` when
invoked as `/report ops`. The first fix attempt rewrote the figure as "22 US cents" but
added an explanatory note that *itself* contains a literal `$0` — so the note
demonstrating the bug is mangled by the bug. Escape it properly.

**Only reproducible by invoking the skill.** Four file-based reviews missed it.

## 6. Things that will bite you

- **`vercel env pull` cannot retrieve production secrets.** They are flagged Sensitive,
  which makes them write-only; the pull returns `"[SENSITIVE]"` placeholders. Supabase
  credentials must come from the Supabase dashboard → Project Settings → API.
- **Supabase caps a `select` at 1000 rows.** The `events` table is far past that, so
  Growth's collector *must* aggregate in Postgres via an RPC. Follow the existing
  pattern in `20260629000000_admin_top_sections.sql` and its siblings.
- **`tsx` transpiles to CommonJS** — `__dirname` works, top-level `await` does not.
- **`timeout` is not installed** on this machine.
- **Node lives under nvm** at `/Users/lauurnce/.nvm/versions/node/v24.18.0/bin` and is
  absent from a clean environment's `PATH`.
- **Vercel `get_runtime_logs` with `group_by` ignores the `since` window on Hobby** —
  `1h` and `7d` return identical counts with no warning. Any "7-day traffic shape" is
  really the last hour. Do not compare it against a 7-day baseline.
- **Active CPU has no API.** It is read by eye at
  `https://vercel.com/lauurnces-projects/~/usage`. Never write an estimate into that
  row — `not read` is the honest entry.
- **PULSE cannot detect a paused Supabase project.** No granted tool can see it. A
  clean report is not proof the database is awake.
- **PULSE cannot measure its own cost** when run as a subagent, so `COST` reads
  `not read`. Real token accounting requires headless `claude -p --output-format json`.

## 7. Next move — the Growth department (VANTAGE)

Write an implementation plan modelled on the Ops one, then execute it with
`superpowers:subagent-driven-development`. The charter is in the spec; the essentials:

**Its first job is to settle the user-count definition.** Auth accounts and the
"signed-up users" figure recorded in `docs/POST-MORTEM.md` differ by roughly an order of
magnitude — most likely because the latter counted *devices* under the device-first
identity model that predates accounts. One metric, one source, one number. Every other
Growth finding is untrustworthy until this is resolved. (Both figures are private —
see `docs/POST-MORTEM.md` and run the collector for the live count.)

**The live funnel is:**
`enter → year_select → subject_open → module_open → paywall_teaser_view →
paywall_teaser_click → subscribe_click`

**`unlock_click` and `unlock_submitted` are dead event types.** They exist in the DB
enum, the events API allowlist, and `lib/supabase/types.ts`, but no code emits them —
pre-pivot leftovers. **`app/admin/page.tsx:29-30` and `AdminDashboard.tsx:867-868` still
render them as live funnel steps**, so the admin dashboard shows two frozen counts that
will never increment. Repairing that display is part of Growth's work.

**There is no completion event on the live path.** `unlock_submitted` was the "they
paid" step and the pivot never replaced it. Conversion completion therefore comes from
the `payments` / `subscriptions` tables joined on device — which is the better source
anyway, since ledger rows are ground truth while a client beacon is lost whenever a
user bounces to GCash and never returns.

**Growth is the expensive build**: a Postgres aggregate migration, RPC wiring, funnel
edge cases, plus the dashboard repair. It also unlocks the council.
