## 6. Things that will bite you

Everything in `HANDOFF-2026-08-05.md` §6 still applies. New this session:

- **Agent definitions load at session start.** After `vantage.md` / `ledger.md` /
  `warden.md` are written, a dispatch in the same session runs a stale definition.
  **Restart the session before the first real run of any new department agent.** This
  already cost one verification run in the previous session.
- **`tsconfig.json` targets ES2017, which rejects the regex `s` (dotAll) flag** with
  TS1501. The Growth plan hit this once at line 1027; the fix was a `RegExp` constructor
  with the same pattern and flag. Only occurrence in the three plans — but worth knowing.
- **Verification docs are the only record of what "passing" means**, since nobody can
  execute them here. **A doc that explains away a symptom is worse than no doc.** Task 6's
  first draft told the owner a persistent Seq Scan "is not itself a failure" and blamed
  table size — which would have permanently masked the dead index. Reviewers must read
  these as deliverables, not as prose.
- **Regression tests that pass against the code they guard protect nothing.** This was the
  recurring defect across Task 3's three rounds: tests written to match the implementation
  rather than to distinguish it from the bug. The re-reviewers caught it by extracting the
  pre-fix function into a scratch script and running the new tests against it. Ask for
  that explicitly.
- **Session limits will interrupt long agent dispatches.** They hit five times over this
  build. Instruct plan-writing and long-form agents to **append each completed section to
  disk as they go** rather than composing everything and writing once at the end — that is
  the difference between resuming and restarting.
- **`.claude/settings.local.json` now sets `defaultMode: acceptEdits`** with a broad
  prefix allowlist and a deny list covering `rm -rf`, `sudo`, force-push, `git reset
  --hard`, `vercel rm`, `supabase db reset`, and `npm publish`. It does **not** deny
  `git filter-branch`.

## 7. Real defects found while planning — none of these needed the agents to exist

These were surfaced by writing and reviewing the plans, and are independent of the
department build.

### 7.1 Semester plan stops being worth anything on 2026-11-30

`lib/paymongo.ts:36-40`. `periodEndFor` floors semester plans at 31 days so a stale
constant can never grant less than a month. But once `from` passes `SEMESTER_END - 31
days`, the semester branch falls through to the same `monthEnd` that `subject_month`
returns — identical access, for the more expensive plan. `SEMESTER_END` is bumped by hand
("Bump once per semester when the selling window rolls over"), so a missed bump makes this
permanent and silent. Both list prices are public in `lib/paymongo.ts`. **Not yet fixed.**

### 7.2 Live database has drifted from the migrations

Seven RPCs are called by application code and defined by **no migration**:
`admin_funnel_counts`, `admin_dau_30d`, `admin_active_since`, `admin_user_totals` (all
from `app/admin/page.tsx`), and `check_login_lockout`, `record_login_attempt`,
`clear_login_attempts` (all from `app/api/admin/login/route.ts` — these gate **admin login
lockout**). Three siblings do have migrations, so the drift is partial. Also
`waitlist.year_label`, `subject_title`, `module_title` are written by
`app/api/waitlist/route.ts` and created by no migration.

`supabase/migrations/20260719010000_api_rate_limits.sql:2` acknowledges this in a comment
("Modeled on the live login_attempts pattern"). **The database cannot be rebuilt from its
migrations today.** This belongs to Operations' data-ops sub-function.

### 7.3 Finance planning found three ledger defects

Detailed in the Finance plan's own "What could not be verified" section:
`recordPayment` overwrites `subscriptions.paymongo_link_id` on renewal (a naive link-id
join would report a **false P0** every month); the `SEMESTER_END` parity above; and an
untransacted webhook path at `app/api/webhooks/paymongo/route.ts:135-178` that inserts the
payment row then the class row with no rollback, so a class-insert failure returns 500
with money recorded and nothing granted.

### 7.4 Security planning found real issues, deliberately not described here

Three findings and one cross-layer observation, named by file only:
`supabase/migrations/20260623_enable_rls.sql`; `lib/deleteAccount.ts` together with the
identity columns declared across `supabase/migrations/`; `package-lock.json`; and a
cross-layer observation spanning `lib/auth/adminSession.ts` and `middleware.ts`.

**Details are withheld from this tracked file on purpose.** A plan or handoff that says
"here is the check, and here is what it found" is a disclosure with a permanent URL. All
four fall inside checks the WARDEN plan builds (Tasks 3, 4, 5, 7) and will surface on the
first private run into `docs/reports/security/`, which is gitignored. Do not go looking
for them in order to write them down.

### Dispatch shape that worked

Give each implementer: one line on where the task fits, the brief path as its single
source of requirements, interfaces from earlier tasks it cannot know, the binding global
constraints, and the report-file path. **Never make a subagent read the whole plan.** Then
generate a review package and dispatch a separate reviewer for spec compliance *and*
quality — the implementer's self-review does not replace it.

Ask reviewers to **verify by execution, not by reading**. Every finding that mattered in
this build came from a reviewer that ran something.

## 10. Working conventions

- Commits: conventional-commit prefixes, **no trailer block ever**, no `Co-Authored-By`.
  The owner is the sole contributor. See `CLAUDE.md`.
- Tests colocate as `<name>.test.ts`.
- Migrations get a `<name>.test.md` verification doc — a real Postgres run, not an assertion.
- No new npm dependencies without a reason.
- Manila dates everywhere (`Asia/Manila`), half-open windows (`>= since`, `< until`).
- Aggregate in Postgres, never in JavaScript — Supabase caps a `select` at 1000 rows.
- `docs/reports/` is gitignored in full and stays that way.
- `superpowers:brainstorming` before creative work, `writing-plans` for plans,
  `subagent-driven-development` to execute them.
